# Чеклист перед сдачей HSEHelper

## Что должно быть сдано по ТЗ

- [ ] **Открытый репозиторий GitHub** (`Public`) со всем исходным кодом и `README.md`.
- [ ] **Отчёт фактического тестирования 30 вопросов** — выходной файл `docs/Результаты_фактического_прогона.md`, созданный скриптом; ответы вручную оценены `PASS` / `PARTIAL` / `FAIL`.
- [ ] **Презентация** `docs/Презентация_HSEHelper.pptx`.
- [ ] В материалах есть инструкция запуска и ссылка на публичный Telegram-бот: [@HSEHelperIVTbot](https://t.me/HSEHelperIVTbot).

## Что сделать на компьютере

1. Запусти `install_local.bat` и проверь, что в `.env` указан свой `GEMINI_API_KEY`.
2. Проверь базу `data/courses.json`. Если её нет, запусти `collect_courses.bat` и убедись, что каталог относится к первому курсу за 2026/2027 год. Не считай `--limit 30` гарантией полного каталога.
3. Выполни `run_local_tests.bat` и сохрани вывод, если проверки прошли.
4. Запусти `start_site.bat`, открой `http://127.0.0.1:8000/health`, затем проверь интерфейс.
5. В отдельном окне запусти `start_telegram_bot.bat`. Открой [@HSEHelperIVTbot](https://t.me/HSEHelperIVTbot), нажми «Start» и задай тестовый вопрос.
6. Пока API и бот запущены, выполни фактический benchmark из корня проекта:

   ```powershell
   .venv\Scripts\python.exe run_benchmark.py --url http://127.0.0.1:8000 --delay 4.5 --output docs/Результаты_фактического_прогона.md
   ```

7. Открой `docs/Результаты_фактического_прогона.md` и вручную оцени каждый из 30 ответов. `HTTP 200` означает только, что запрос обработан, а не то, что ответ верен. Не называй эталонные ответы фактическими результатами.

## Как опубликовать на GitHub

1. Создай новый репозиторий с видимостью **Public**.
2. Из корневой папки проекта выполни команды, заменив `USERNAME` на свой логин и `HSEHelper` на имя репозитория:

   ```bash
   git init
   git add .
   git status
   git commit -m "HSEHelper prototype"
   git branch -M main
   git remote add origin https://github.com/USERNAME/HSEHelper.git
   git push -u origin main
   ```

3. Перед `git commit` проверь `git status`: в списке не должно быть `.env`, токена Telegram, ключа Gemini, `.venv/`, `data/courses.json`, `data/chat_history.sqlite3` или файлов `__pycache__`.
4. Открой ссылку на репозиторий в приватном окне браузера и проверь, что доступ публичный.

## Telegram-демо

- Публичная ссылка: https://t.me/HSEHelperIVTbot
- Во время демонстрации должны работать **оба локальных процесса**: API (`start_site.bat`) и polling-бот (`start_telegram_bot.bat`).
- Если компьютер выключен/спит или сеть блокирует `api.telegram.org`, Telegram-бот не ответит. Сам факт существования публичной ссылки не означает, что бот работает постоянно.
- Никогда не публикуй `TELEGRAM_BOT_TOKEN` или `GEMINI_API_KEY`.
