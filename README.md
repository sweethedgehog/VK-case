# HSEHelper — помощник по учебным дисциплинам ИВТ МИЭМ НИУ ВШЭ

HSEHelper — прототип информационного помощника для студентов первого курса направления ИВТ МИЭМ НИУ ВШЭ. Он отвечает на вопросы о содержании учебных дисциплин по собранным публичным программам курсов, старается давать краткие ответы и возвращает ссылки на источники.

**Учебный период:** 2026/2027 учебный год.  
**Источник данных:** [официальный каталог дисциплин ИВТ МИЭМ](https://www.hse.ru/ba/isct/courses?course=1.1.1.4&page=1&year=2026).  
**Telegram-бот:** [@HSEHelperIVTbot](https://t.me/HSEHelperIVTbot).

> Проект является учебным прототипом. Сведения о дисциплинах следует сверять с официальными страницами ВШЭ. Помощник не заменяет учебный офис и не должен угадывать сведения, которых нет в собранных источниках.

## Возможности

- Сбор публичных страниц программ дисциплин в локальный JSON-каталог.
- Поиск подходящих фрагментов по названиям, словам и известным сокращениям.
- Формирование ответа с помощью Gemini API на основе найденного контекста.
- Отображение официальных URL источников рядом с ответом.
- Локальный веб-интерфейс и HTTP API на FastAPI.
- Необязательный Telegram-интерфейс, использующий тот же API.
- Набор из 30 тестовых сценариев: 20 для проверки полезных возможностей и 10 для оценки ограничений.

## Архитектура

```text
Каталог программ ВШЭ
        |
        v
scrape_hse.py ---> data/courses.json
                         |
                         v
Веб-интерфейс ---> server.py ---> assistant.py ---> Gemini API
                         ^             |
                         |             v
                    bot.py        Поиск и источники
```

Основные модули:

| Файл | Назначение |
|---|---|
| `scrape_hse.py` | Получение и обработка публичных страниц программ дисциплин |
| `query_utils.py` | Нормализация запросов, обработка сокращений и извлечение данных |
| `semantic_search.py` | Работа с фрагментами текста и дополнительным семантическим поиском |
| `assistant.py` | Поиск контекста и формирование ответа через Gemini API |
| `server.py` | Веб-интерфейс и HTTP API на FastAPI |
| `bot.py` | Telegram-бот на aiogram |
| `conversation_store.py` | Локальное хранение истории диалогов |
| `web/` | HTML, CSS и JavaScript веб-интерфейса |
| `benchmark_cases.json` | 30 сценариев для тестирования |
| `run_benchmark.py` | Отправка набора тестовых вопросов работающему API |
| `tests.py`, `api_smoke_tests.py` | Автоматические проверки поисковых функций и API |

## Требования

Для локального запуска на Windows:

- Python 3.12 (рекомендуется) или совместимая версия Python 3;
- доступ к интернету для Gemini API и, при сборе данных, к сайту ВШЭ;
- ключ Gemini API;
- для Telegram-бота — токен бота и возможность подключения к `api.telegram.org`.

VPS и Docker для локальной демонстрации не требуются.

## Быстрый запуск на Windows

### 1. Установка зависимостей

Склонируйте репозиторий или скачайте его архивом. Откройте папку проекта и запустите:

```text
install_local.bat
```

Скрипт создаёт виртуальное окружение `.venv`, устанавливает облегчённые зависимости для сайта и API и создаёт `.env` на основе `.env.local.example`, если настройки ещё не существуют.

### 2. Настройка окружения

Создайте ключ в [Google AI Studio](https://aistudio.google.com/apikey). Откройте `.env` и укажите ключ:

```dotenv
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
GEMINI_MODEL=gemini-3.5-flash-lite
SEARCH_MODE=keyword
```

В `.env` могут также находиться дополнительные параметры модели, ограничения контекста и Telegram-токен. Их названия и значения берутся из `.env.example` или `.env.local.example`.

**Не публикуйте `.env` и не добавляйте в GitHub реальные ключи API или токен Telegram.** Файл `.env` исключён в `.gitignore`.

### 3. Подготовка каталога дисциплин

Если файл `data/courses.json` уже подготовлен, поместите его в каталог `data/`.

Чтобы собрать программы заново, запустите:

```text
collect_courses.bat
```

Команда сборщика, используемая скриптом:

```powershell
.venv\Scripts\python.exe scrape_hse.py --limit 30 --max-pages 5 --year 2026 --course-filter 1.1.1.4
```

Параметр `--limit 30` ограничивает размер прототипа; это не гарантия полноты всего каталога. После сбора следует проверить количество записей, учебный год и наличие официальных ссылок.

### 4. Запуск сайта и API

Запустите:

```text
start_site.bat
```

Не закрывайте окно терминала, пока приложение используется. Откройте в браузере:

- Веб-сайт: <http://127.0.0.1:8000>
- Проверка состояния: <http://127.0.0.1:8000/health>
- Статус каталога: <http://127.0.0.1:8000/api/status>
- Список дисциплин: <http://127.0.0.1:8000/api/courses>
- Документация API: <http://127.0.0.1:8000/docs>

Сайт привязан к `127.0.0.1`, то есть по умолчанию доступен только на компьютере, где он запущен.

## Запуск Telegram-бота

Публичная ссылка: [@HSEHelperIVTbot](https://t.me/HSEHelperIVTbot).

Бот использует API, запущенный вместе с сайтом. Для локальной работы необходимы два работающих процесса:

1. `start_site.bat` — сайт и API;
2. `start_telegram_bot.bat` — Telegram-бот.

Перед запуском бота укажите токен в `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
API_BASE_URL=http://127.0.0.1:8000
```

Один раз установите дополнительные зависимости с помощью `install_telegram.bat`, затем запустите `start_telegram_bot.bat`. Для ответа ботом компьютер должен быть включён, оба процесса должны работать, а сеть должна разрешать соединение с `api.telegram.org`. Если локальный API остановить, бот не сможет передавать ему вопросы.

## API

### `GET /health`

Проверка доступности приложения.

### `GET /api/status`

Состояние каталога и приложения.

### `GET /api/courses`

Получение списка дисциплин, доступных в локальном каталоге.

### `POST /api/ask`

Пример тела запроса:

```json
{
  "question": "Что изучают на математическом анализе?",
  "session_id": "demo-001"
}
```

Ответ содержит текст ответа, ссылки на источники и идентификатор сессии.

## Тестирование

### Автоматические проверки

После установки зависимостей запустите:

```text
run_local_tests.bat
```

Или вручную:

```powershell
.venv\Scripts\python.exe tests.py
.venv\Scripts\python.exe api_smoke_tests.py
```

### Проверка на 30 вопросах

Набор сценариев находится в `benchmark_cases.json`; критерии и эталонные ориентиры — в `docs/Тестирование_30_вопросов.md`.

При запущенном сайте, заполненном каталоге и настроенном Gemini API выполните:

```powershell
.venv\Scripts\python.exe run_benchmark.py --url http://127.0.0.1:8000 --delay 4.5 --output docs/Результаты_фактического_прогона.md
```

Скрипт сохранит реальные ответы, статусы запросов и найденные источники. После прогона необходимо проверить каждый ответ и отметить результат, например `PASS`, `PARTIAL` или `FAIL`. Подготовленный набор вопросов не является фактическим отчётом о выполнении тестов. Ошибки API и случаи исчерпания квоты следует сохранять в отчёте как есть.

## Ограничения

- В режиме `SEARCH_MODE=keyword` поиск основан на словах и алиасах; он быстрее запускается и не требует загрузки embedding-модели, но хуже понимает некоторые смысловые перефразировки.
- Вызов Gemini требует интернет-соединения, действительного ключа и доступной квоты. Перегрузка провайдера может временно прервать генерацию.
- Полнота и точность ответа зависят от реально собранных страниц. Лимит сбора не гарантирует загрузку всех дисциплин первого курса.
- Сведения о преподавателях, оценивании и литературе приводятся только в той мере, в какой они присутствуют в доступных источниках.
- Программа дисциплины не обязательно содержит расписание и распределение преподавателей по академическим группам.
- Telegram-бот в этой версии не является постоянно работающим облачным сервисом: при локальном запуске он зависит от компьютера разработчика и доступности сети.

## Безопасность и публикация

Перед публикацией репозитория проверьте, что в него не попали:

- `.env`, токены Telegram и ключи внешних API;
- виртуальное окружение `.venv/`;
- история пользовательских диалогов и локальные логи;
- кэш embeddings и временные файлы.

Эти данные перечислены в `.gitignore`. Конфигурация для примера должна содержать только заглушки, а не действующие секреты.
